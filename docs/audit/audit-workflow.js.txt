// pendant que le workflow de la première version tournait encore : vérifier qu'aucun autre workflow ne tourne.
//
// Pour le relancer depuis une autre session :
//   args = { blocNotes: '<dossier temporaire de la session>', rapports: ['architecture-application', …], voies: 1,
//            etats: { 'architecture-application': { fait: 'audit' } } }

// { fait: 'réfutation', ajoutes: n } quand il ne reste que n constats ajoutés à contre-vérifier. Sans etats, un
// rapport part de l'audit (et l'agent reprend le fichier s'il existe). Les rapports finis ne sont pas à lister.
// docs/audit/fiches.md, rapport partiel de la première version que les missions des fiches citent, a été retiré le
// 13 novembre, une fois ses constats repris par les deux rapports des fiches (il reste dans l'historique).
// et recréer dans ce dossier le script d'envoi « envoi-audit.sh » : sous un verrou (flock), il refuse tout fichier

// chemin local, aucun nom de modèle d'intelligence artificielle), fait « git add » et « git commit » de ce seul
// fichier (auteur : Julien, adresse « noreply » ; committer : l'identité par défaut de l'environnement), puis
// « git push origin <branche> » avec reprises. Les agents n'utilisent jamais git autrement.
// Un rapport déjà commencé est repris, pas refait : les consignes de reprise sont dans les missions.

const RESUME = {
  type: 'object',
  properties: {
    fichier: { type: 'string' }, pousse: { type: 'boolean' }, resume: { type: 'string' },
    constats: { type: 'number' }, verifies: { type: 'number' }, perimetre_non_couvert: { type: 'string' },
  },
  required: ['fichier', 'pousse', 'resume', 'constats'],
}
const VERDICTS = {
  type: 'object',
  properties: {
    pousse: { type: 'boolean' }, confirmes: { type: 'number' }, refutes: { type: 'number' }, ajoutes: { type: 'number' },
    resume: { type: 'string' },
  },
  required: ['pousse', 'confirmes', 'refutes', 'ajoutes', 'resume'],

const audit = (r) => agent(`${commun(r)}

Mission : écrire le rapport d'audit « ${r.titre} » et l'envoyer.
Périmètre : ${r.perimetre}

Reprise : ${r.reprise || `si ${W}/${r.fichier} existe déjà, un agent avant toi a été coupé en plein travail (limite d'usage). Ne repars pas de zéro : lis-le, garde ce qui est écrit et prouvé, et continue là où il s'est arrêté (la partie du périmètre qu'il n'a pas traitée) ; son dossier de travail, ${S}/audit/${r.cle}/, est peut-être encore là.`}

Écris ${W}/${r.fichier} (français), au fur et à mesure :
- en tête : titre, date, périmètre, méthode, sources relues et non relues, et la ligne « État : constats non contre-vérifiés » ;
- section « ## Constats » : un constat par titre de niveau 3, « ### ${r.prefixe}-01 · gravité · titre », numérotés à la suite, gravité parmi « faux » (contraire à la source, au calcul ou au code), « non sourcé », « incohérent » (code, documentation et fiches ne disent pas la même chose), « à améliorer » (juste mais trompeur, obscur, irréaliste sans être dit, ou source de dette) ; puis l'endroit exact (fichier et ligne), ce qui est écrit ou fait, la preuve (citation exacte de la source avec son adresse, calcul refait avec ses nombres, extrait de code, mesure), et la correction proposée, précise et proportionnée ;
- section « ## Vérifié » : les points contrôlés et justes, une ligne chacun ;

- les sections propres à ton périmètre, s'il en demande.
Classe les constats du plus grave au moins grave à la fin (les identifiants peuvent alors ne plus se suivre : ne les renumérote pas après un envoi). Pas de constat sans preuve. Dis dans l'en-tête ce que tu n'as pas eu le temps de couvrir.

Réponds par l'objet structuré : fichier, pousse (vrai si le script a écrit « ENVOYÉ » pour ton dernier état), resume (120 mots au plus), constats (nombre), verifies (nombre), perimetre_non_couvert (ce qui reste à auditer, ou « rien »).`,
  { label: `audit ${r.cle}`, phase: 'Audit', schema: RESUME, agentType: 'general-purpose' })

const refutation = (r) => agent(`${commun(r)}

Mission : essayer de réfuter, un par un, tous les constats du rapport ${W}/${r.fichier} (« ${r.titre} »), écrit par un autre agent, puis envoyer le rapport annoté.
Tu es l'avocat du travail audité. Pour chaque constat (titres « ### ${r.prefixe}-… ») : relis toi-même l'endroit visé et la source à son adresse, ou refais le calcul ou l'essai avec ton propre script (sous ton dossier de travail, dans un sous-dossier refutation/), sans reprendre les scripts de l'audit, et cherche si le constat est faux, exagéré, déjà dit ailleurs dans le dépôt, hors du périmètre (travail fait le 12 novembre 2026 ou après), ou si sa correction introduirait une erreur ou une dette. Dans le doute, le constat est réfuté.
Écris sous chaque constat une ligne « **Contre-vérification : confirmé.** » ou « **Contre-vérification : réfuté.** », suivie de ta preuve en une à trois phrases ; corrige la correction proposée quand elle est fausse ou disproportionnée, et la gravité quand elle est exagérée. Si le rapport a des sections de plan ou de recommandations, écris sous chaque recommandation que tu contestes une ligne « **Contre-avis :** » avec tes raisons. Si tu trouves en chemin une faute que le rapport n'a pas vue, ajoute-la en fin de section « Constats », numérotée à la suite, avec la mention « ajouté à la contre-vérification » dans son titre, sa preuve et sa correction (elle sera contre-vérifiée par un troisième agent : n'écris pas de verdict dessous). Quand tout est traité, remplace en tête la ligne d'état par le bilan : date, constats confirmés, réfutés, ajoutés, et en une phrase ce qui est à corriger d'abord ; retire toute mention qui dit que le rapport n'est pas contre-vérifié.

Reprise : si des constats portent déjà une ligne « Contre-vérification », un agent avant toi a été coupé en plein travail : ne les refais pas, continue avec les suivants.

Réponds par l'objet structuré : pousse (vrai si le script a écrit « ENVOYÉ » pour ton dernier état), confirmes, refutes, ajoutes (nombres, sur tout le rapport), resume (120 mots au plus : ce qui est vraiment à corriger, du plus grave au moins grave).`,
  { label: `réfutation ${r.cle}`, phase: 'Réfutation', schema: VERDICTS, agentType: 'general-purpose' })

const ajoutes = (r) => agent(`${commun(r)}

Mission : contre-vérifier les constats ajoutés pendant la contre-vérification du rapport ${W}/${r.fichier} (« ${r.titre} »), puis envoyer le rapport annoté.
Le rapport a été écrit par un premier agent ; un second a essayé de réfuter chaque constat et en a ajouté, marqués « ajouté à la contre-vérification ». Règle du projet : un constat n'est corrigé que s'il a été contre-vérifié par un second agent ; ceux-là ne l'ont été par personne. Pour chaque constat ajouté qui n'a pas encore de ligne « Contre-vérification » : relis toi-même l'endroit visé et la source à son adresse, ou refais le calcul ou l'essai avec ton propre script, et cherche s'il est faux, exagéré, déjà dit ailleurs dans le dépôt, hors du périmètre, ou si sa correction introduirait une erreur ou une dette. Dans le doute, le constat est réfuté. Écris dessous « **Contre-vérification : confirmé.** » ou « **Contre-vérification : réfuté.** », suivie de ta preuve en une à trois phrases ; corrige la correction proposée si elle est fausse ou disproportionnée. Ne touche pas aux autres constats. Mets à jour le bilan en tête du rapport : parmi les constats ajoutés, combien sont confirmés, combien réfutés.

Réponds par l'objet structuré : pousse (vrai si le script a écrit « ENVOYÉ » pour ton dernier état), confirmes, refutes (nombres, pour les seuls constats ajoutés), ajoutes (0), resume (80 mots au plus).`,
  { label: `ajoutés ${r.cle}`, phase: 'Constats ajoutés', schema: VERDICTS, agentType: 'general-purpose' })

// Une voie par défaut (deux au plus : l'outil ne mène que deux agents de front sur cette machine) ; dans une voie,
// un rapport est mené jusqu'au bout (audit, réfutation, constats ajoutés) avant le suivant : une coupure laisse
// ainsi des rapports finis plutôt que des audits sans réfutation.
const chaine = async (r) => {
  const etat = { rapport: r.cle, fichier: r.fichier, coupe: null, audit: null, refutation: null, ajoutes: null }
  if (r.fait) {
    etat.audit = 'déjà fait'
  } else {
    etat.audit = await audit(r)
    if (!etat.audit) { log(`${r.cle} : audit coupé`); etat.coupe = 'audit'; return etat }
  }
  if (r.fait === 'réfutation') {
    etat.refutation = { ajoutes: r.ajoutes, resume: 'déjà faite' }
  } else {
    etat.refutation = await refutation(r)
    if (!etat.refutation) { log(`${r.cle} : réfutation coupée`); etat.coupe = 'réfutation'; return etat }
    log(`${r.cle} : ${etat.refutation.confirmes} confirmé(s), ${etat.refutation.refutes} réfuté(s), ${etat.refutation.ajoutes} ajouté(s)`)
  }
  if (etat.refutation.ajoutes > 0) {
    etat.ajoutes = await ajoutes(r)
    if (!etat.ajoutes) { log(`${r.cle} : contre-vérification des constats ajoutés coupée`); etat.coupe = 'constats ajoutés'; return etat }
    log(`${r.cle}, constats ajoutés : ${etat.ajoutes.confirmes} confirmé(s), ${etat.ajoutes.refutes} réfuté(s)`)
  }
  return etat
}
const cles = (args && args.rapports) || Object.keys(RAPPORTS)
const nombre = Math.min(2, Math.max(1, (args && args.voies) || 1))
const voies = Array.from({ length: nombre }, () => [])
const etats = (args && args.etats) || {}
cles.forEach((cle, i) => voies[i % nombre].push({ ...RAPPORTS[cle], cle, ...(etats[cle] || {}) }))
const parVoie = await parallel(voies.map((voie) => async () => {
  const faits = []
  for (const r of voie) faits.push(await chaine(r))
  return faits
}))
return parVoie.filter(Boolean).flat()
