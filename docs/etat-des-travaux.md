## Méthode

Pour une fonction nouvelle :
1. un dossier de sources : citations exactes des manuels des boîtiers, relues une seconde fois à la source par un agent indépendant ; gardé dans `docs/dossiers/`, avec en tête la mention « pas encore relu » tant que ce n'est pas fait ;
2. une spécification, critiquée sous deux angles (fidélité aux sources ; débutant, interface et code), puis révisée ; gardée dans `docs/specifications/` ;
3. la mise en œuvre, relue sous trois angles (correction du code ; sources et vérité ; interface et mobile), puis corrigée ;
4. la pull request, avec la routine de test lancée par la CI.

Quand le dossier ou la spécification d'une fonction de la file sont dans le dépôt, les lire d'abord ; sinon, les refaire.

Pour un sujet du plan de corrections (Sujets 1 à 4) : une mise en œuvre ; deux relecteurs, chacun sous un angle ; un agent qui cherche d'abord à réfuter chaque constat, puis corrige ce qui tient ; un contrôle final par un agent qui n'a rien écrit de la version ; deux tours au plus. Pour refaire un audit : `docs/audit/audit-workflow.js.txt`, `docs/audit/synthese-workflow.js.txt` et `docs/audit/consignes-agents.md` (leurs en-têtes disent comment les lancer et les reprendre).
